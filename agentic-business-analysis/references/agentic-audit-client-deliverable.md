# Agentic Business Audit — Client Report Template

Use this structure after intake and process analysis.

## Product name options

Pick depending on tone:

- **Agentic Business Audit** — premium/B2B.
- **AI Agent Automation Audit** — clear for automation buyers.
- **Business Process Map for AI Agents** — practical and sober.
- **AI Agent Implementation Roadmap** — when the client already wants implementation.

## Cover

```text
Agentic Business Audit
For: <client/business>
Goal: identify where AI agents can reduce manual work, speed up operations, and improve control without unsafe autonomy.
Version / date
```

## 1. Executive summary

Include:

- main bottleneck;
- best first automation opportunity;
- recommended first pilot;
- expected operational effect, stated carefully;
- key risk / approval gate.

Example:

```text
The best first pilot is not “automate the whole sales department”. Start with incoming request processing: an agent structures the message, extracts key fields, checks missing data, prepares a CRM update, and escalates hot leads to the manager. This creates a visible effect without giving the agent permission to promise prices or deadlines independently.
```

- Customer segments.
- Main value chain.
- Team and roles.
- Current tools.
- Main repeated processes.
- Current pain.

## 4. Bottlenecks and manual load

Group by type:

- lost leads / slow response;
- manual copy-paste between tools;
- CRM chaos;
- repeated client questions;
- manual reports;
- document drafting;
- knowledge scattered across chats or people's heads;
- no control over task status.

## 6. Proposed agent contour

Start with business explanation, then technical shape.

Example:

```text
The first contour should not be a “smart bot for everything”. Use three responsibilities:

1. Intake Agent — receives and structures incoming requests.
2. CRM Agent — prepares CRM updates and monitors stale deals.
3. Supervisor Agent — produces a daily report and escalates unclear cases.
```

## 7. Interaction architecture

Describe one of:

- single assistant;
- pipeline;
- supervisor-worker;
- fan-out/fan-in;
- workflow engine + agents;
- human-in-the-loop.

Include a simple flow:

```text
Telegram/site form -> Intake Agent -> CRM update draft -> Manager approval -> CRM update + follow-up reminder -> Daily report
```

- Knowledge base/SOPs needed.
- API/webhooks or workaround.
- Logging.
- Privacy constraints.

## 9. Pilot scope: 2-4 weeks

```text
Pilot goal:
Included:
Excluded:

Data sources:

Deliverables:

Client-side owner:
```

Good acceptance criteria examples:

- 90%+ incoming leads are structured into required fields.
- Daily report generated by 10:00 with no manual compilation.
- Support drafts cover top 20 FAQs with human approval.
- CRM stale deals report catches missed follow-ups daily.

Avoid promising revenue growth unless baseline data supports the claim. Use “pilot hypothesis” when data is incomplete.

## 10. Roadmap after pilot

- Phase 1: audit and data cleanup.
- Phase 2: first agent/workflow pilot.
- Phase 3: integrations and reporting.
- Phase 4: multi-agent expansion.
- Phase 5: support and iteration.

## 11. Risks and controls

- Technical: API access, unstable tools, data quality.
- Operational: no owner, staff resistance, messy process.
- Legal/formal: claims, personal data, regulated advice.
- Finance: unclear ROI, hidden subscription costs.
- Reputation: bad client-facing messages.

## 12. Questions / decisions needed

Only unresolved blockers.

## Language rules

Say:

- “the agent prepares a draft answer” instead of “the agent replaces the manager”;
- “approval before client-facing action” instead of “full autonomy”;
- “pilot hypothesis” instead of “guaranteed result”;
- “source of truth” only if explained as “where correct information lives”.

Do not say:

- “AI will automate everything”;
- “we will replace employees”;
- “sales growth is guaranteed”;
- “fully autonomous business”.

## Delivery quality checklist

- [ ] There is a clear first pilot, not 15 unrelated ideas.
- [ ] Agent responsibilities are business-readable.
- [ ] Approval gates are explicit.
- [ ] Data and integration requirements are explicit.
- [ ] Risks are named directly.
- [ ] No revenue guarantees.
